# iOS 桌面宠物设计说明

## 目标

交付一个可放入 Xcode 运行的 SwiftUI iOS 工程。应用打开后显示一个“手机桌面”场景，猫和虎皮鹦鹉在场景内持续轻微蹦跳；用户点击其中一只后，该宠物停止动画，并在头顶显示第三张图片的摸头表情，约 2 秒后自动恢复。

## 平台边界

iOS 不允许普通应用在系统主屏幕上持续绘制可交互的漂浮角色，因此第一版把“桌面宠物”实现为应用内的全屏桌面场景。后续如需系统主屏幕入口，可复用 `Pet` 状态和资源扩展为小组件，但小组件不能提供同样的持续动画和点击反馈。

## 用户体验

- 背景使用柔和的蓝紫渐变，叠加轻微半透明圆形装饰，保持宠物轮廓清晰。
- 猫和虎皮鹦鹉位于屏幕下半部左右两侧，保持足够间距，避免点击区域重叠。
- 两只宠物分别以不同相位上下弹跳，并有少量左右摇摆；动画循环平滑，不依赖网络。
- 点击某只宠物后，只暂停被点击的宠物；该宠物显示第三张图片的“摸摸头”反馈。反馈以缩放和淡入出现，2 秒后淡出并自动恢复蹦跳。
- 点击期间仍可点击另一只宠物；每只宠物有独立的暂停计时和反馈状态。
- 支持 Dynamic Type 和 VoiceOver：点击区域使用明确的可访问标签，例如“猫，点击摸摸头”。

## 方案与架构

采用 SwiftUI 原生方案，不引入 SpriteKit 或第三方依赖。

### `Pet`

值类型模型，保存角色 id、名称、资源名、初始位置、动画相位和可访问描述。

### `PetStageView`

负责场景背景、布局和两个宠物实例。使用 `GeometryReader` 将宠物位置按容器宽高计算，适配不同 iPhone 尺寸和横竖屏安全区。

### `PetView`

负责单只宠物的图片、弹跳动画、点击区域和反馈贴纸。通过 `TimelineView(.animation)` 根据时间计算平滑的垂直偏移与轻微旋转；点击后记录 `pausedUntil`，在时间窗口内固定位置并显示反馈。

### `PatStickerView`

负责第三张图片的反馈层，使用 `opacity`、`scaleEffect` 和阴影完成出现/消失动画。贴纸锚定在宠物头部附近，不参与宠物本身的位移计算。

### 资源目录

- `cat.png`：第一张宠物图，外部白底转为透明。
- `budgie.png`：第二张宠物图，外部白底转为透明。
- `pat-sticker.webp`：第三张摸头表情图；若 Xcode 资源目录不接受 WebP，则在导入阶段转为 PNG。

## 资源处理

对前两张 JPG 从四角做连通区域抠图，仅移除与边缘相连的白色背景，保留猫身和鸟身内部的白色。输出为带 alpha 通道的 PNG，并保留原始比例。第三张图保持完整构图，作为带透明边缘的贴纸使用；如果源文件在当前工作区不可访问，则保留 `pat-sticker` 资源占位，并在工程 README 中标注替换位置。

## 状态与动画流程

1. 初始状态：`isPatted = false`，宠物按自身相位持续移动。
2. 点击宠物：设置 `isPatted = true`，记录当前动画位置，显示贴纸并启动 2 秒恢复任务。
3. 恢复任务结束：设置 `isPatted = false`，贴纸淡出，动画从当前时间相位自然继续。
4. 若恢复前再次点击同一宠物，刷新 2 秒计时，不叠加多个任务。
5. 点击另一只宠物只改变另一只的状态。

## 测试与验收

- 在 iPhone 15 模拟器尺寸下运行，确认两只宠物都能持续循环移动。
- 点击猫：猫立即停止并出现贴纸，约 2 秒后恢复；鹦鹉运动不受影响。
- 点击鹦鹉：鹦鹉立即停止并出现贴纸，约 2 秒后恢复；猫运动不受影响。
- 连续点击同一宠物，确认计时刷新且不会出现多个贴纸残留。
- 旋转或切换不同屏幕尺寸，确认宠物不被安全区裁切，点击区域仍跟随图片。
- 在 VoiceOver 下确认两个宠物均可被识别和操作。

## 非目标

- 不实现后台持续运行、锁屏悬浮、系统主屏幕自由拖动或网络同步。
- 不加入喂食、对话、商店等额外玩法，保持第一版范围聚焦于动画和点击反馈。
